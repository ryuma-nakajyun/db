# 小数点の桁数
GISでマスタデータとして保持する緯度経度の桁数は、  
用途によりますが 小数点以下6〜7桁が一般的 です。  

小数点以下桁数	誤差の目安
```text
3桁	約111m
4桁	約11m
5桁	約1.1m
6桁	約11cm
7桁	約1.1cm
8桁	約1mm
```
例えば東京駅は
```text
35.681236
139.767125
```
のように小数点以下6桁程度で表現できます。

実務では次のような傾向があります。
```text
地図表示のみ → 5〜6桁
住所・施設マスタ → 6桁
GPS測位データ → 6〜7桁
測量・基準点 → 7桁以上
```

ただし、GPS自体の精度が数m程度であることが多いため、業務システムのマスタでは
```sql
DECIMAL(9,6)
```
または
```sql
DECIMAL(10,7)
```
で保持することがよくあります。

自治体や企業の施設マスタ、店舗マスタであれば 小数点以下6桁（約11cm精度）を採用するのが無難 です。  
桁数を増やしても元データの精度以上にはならず、比較処理やデータ量だけが増えるためです。  

DBに保存する場合は、通常は10進数（Decimal Degrees, DD）で保存します。

例えば、
```text
43°03′52″ → 60進数表記
43.064444 → 10進数表記
```
です。

先日聞いていた座標
```text
43°03′52″
```
を10進数へ変換すると、
```text
43 + 3/60 + 52/3600
= 43.064444...
```
になります。

GISや地図APIではほぼ10進数が使われています。
例:
```text
latitude  = 43.064444
longitude = 141.346944
```
**Google Maps**、**OpenStreetMap**、**PostGIS**なども基本的に10進数です。

DB定義例:
```sql
latitude  DECIMAL(10,7)
longitude DECIMAL(10,7)
```
または
```sql
latitude  DOUBLE
longitude DOUBLE
```

実務では
入力時: 60進数でも可
DB保存: 10進数
画面表示: 必要に応じて60進数へ変換
という構成が一般的です。

理由は、距離計算・範囲検索・GIS処理が10進数の方が圧倒的に扱いやすいためです。
60進数のままDBに持つことはほとんどありません。


# DECIMAL
GIS用途なら、DECIMALを推奨します。

違いを簡単に言うと、
型	特徴DECIMAL	正確な値を保存
DOUBLE	近似値を保存

例:
```text
43.064444
```

を保存すると、
```text
DECIMAL(9,6)
```
なら
```text
43.064444
```
がそのまま保持されます。
一方、
DOUBLE
は内部的には2進数で保持するため、
43.06444400000001
のような誤差が発生する可能性があります。

GISでの使い分け
マスタデータ

住所マスタや施設マスタなど
```sql
latitude  DECIMAL(10,7)
longitude DECIMAL(10,7)
```
が多いです。

理由は、
入力値をそのまま保持したい
データ連携時に誤差を出したくない
ためです。

GISエンジン
PostGISなどのGISエンジン内部では
DOUBLE PRECISION

を使うことがあります。

理由は、
距離計算
面積計算
座標変換
などの計算速度が速いためです。

Javaとの関係
Javaなら
BigDecimal
⇔
DECIMAL
double
⇔
DOUBLE
が対応します。

実務のおすすめ
施設マスタや住所マスタなら
```sql
latitude  DECIMAL(10,7)
longitude DECIMAL(10,7)
```
で十分です。

緯度の最大値は ±90、経度は ±180 なので、
```sql
DECIMAL(10,7)
```
なら
```text
90.1234567
180.1234567
```
まで保存でき、約1cm精度になります。

隆磨さんが以前扱っていた「都道府県コードを0埋めしてDBに保持する」話と同じで、
マスタデータは計算のしやすさよりも値を正確に保持することを優先するのが基本です。
その観点では GIS の座標も DECIMAL のほうが設計意図が明確です。


#　
GISで扱う座標は、「元データの精度」と「DBで保持する桁数」を分けて考えると整理しやすいです。

小数点桁数と精度  
緯度経度を10進数で表現した場合
| 小数点以下 | 精度の目安 |
| -----------| -----------| 
| 1桁 | 約11km | 
| 2桁 | 約1.1km | 
| 3桁 | 約111m | 
| 4桁 | 約11m | 
| 5桁 | 約1.1m | 
| 6桁 | 約11cm | 
| 7桁 | 約1.1cm | 

例
```text
43.0644444
```
を丸めると
```text
43.0644444   元データ
43.064444    小数点6桁
43.06444     小数点5桁
43.0644      小数点4桁
```
になります。

丸め方  
一般的には四捨五入です。  

Java
```java
BigDecimal lat = BigDecimal.valueOf(43.0644444);
lat = lat.setScale(6, RoundingMode.HALF_UP);
System.out.println(lat);
```
結果
43.064444

例えば
43.0644446
なら
43.064445
になります。

DB設計の考え方
施設マスタ
施設の位置を示すだけなら

DECIMAL(9,6)

十分です。

例
```sql
latitude  DECIMAL(9,6)
longitude DECIMAL(10,6)
```

精度
約11cm
住所マスタ
住所ジオコーディングも
DECIMAL(9,6)
が多いです。

建物単位で十分な精度があります。
GPSログ
移動履歴や測位データなら
DECIMAL(10,7)
または
DOUBLE
が使われます。

実務でよく見る保持方針
パターン1
```text
元データ
43.0644447
DB
43.064445
(小数点6桁で四捨五入)
```

パターン2
```text
元データをそのまま保持
DECIMAL(10,7)
43.0644447
そのまま保存
画面表示だけ
43.064445
へ丸める。
```

個人的におすすめ
マスタデータなら
```sql
latitude  DECIMAL(10,7)
longitude DECIMAL(10,7)
```
で保持し、

表示時だけ
```java
setScale(6, RoundingMode.HALF_UP)
```
で6桁にする設計です。

理由は、  
元データを失わない  
将来精度要件が上がっても再取り込み不要  
表示の見やすさは別制御できる  
からです。  

システム設計書に書くなら、  
緯度経度は10進数形式で保持し、  
DBは DECIMAL(10,7) を使用する。  
表示時は小数点以下6桁へ四捨五入する。  
という記載だと実務的に自然です。  

# 座標チェック用の制約DDLを作って
緯度経度を10進数で保持する前提なら、DB制約でチェックしておくと不正データを防げます。

緯度・経度の有効範囲は以下です。
```text
緯度(Latitude)  : -90 ～ 90
経度(Longitude) : -180 ～ 180
```

PostgreSQL
```sql
CREATE TABLE location (
    id BIGSERIAL PRIMARY KEY,
    latitude  DECIMAL(10,7) NOT NULL,
    longitude DECIMAL(10,7) NOT NULL,

    CONSTRAINT chk_latitude
        CHECK (latitude BETWEEN -90.0 AND 90.0),

    CONSTRAINT chk_longitude
        CHECK (longitude BETWEEN -180.0 AND 180.0)
);
```
より実務的な例

日本国内限定なら範囲をさらに絞れます。
```text
緯度  : 約20 ～ 46
経度  : 約122 ～ 154
```

```sql
CONSTRAINT chk_latitude_jp
    CHECK (latitude BETWEEN 20.0 AND 46.0),

CONSTRAINT chk_longitude_jp
    CHECK (longitude BETWEEN 122.0 AND 154.0)
```

これにより、
```text
999.9999999
や
35.6895
1397.1234
```
のようなデータを登録できなくなります。

システム設計書向け記載例
```text
項目名      : 緯度
型          : DECIMAL(10,7)
必須        : ○
制約        : -90.0000000 ～ 90.0000000

項目名      : 経度
型          : DECIMAL(10,7)
必須        : ○
制約        : -180.0000000 ～ 180.0000000
```

マスタ設計としては、
```sql
latitude  DECIMAL(10,7)
longitude DECIMAL(10,7)
```
＋
```sql
CHECK
```
による範囲制約を付けるのが最も素直で保守しやすい設計です。
