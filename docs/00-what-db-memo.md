# DBとは
- SQLやJOINは後から覚えられますが、DBで本当に重要なのは「なぜその仕組みが存在するか」です。

### 1. DBは「状態」を管理する
```text
プログラムは計算します。
入力
 ↓
処理
 ↓
出力
```
しかし処理が終わると消えます。  

一方DBは
```text
過去
現在
未来
```
に渡って状態を保持します。

例えば銀行。
A口座: 100万円  
これは「計算結果」ではなく、  
現在の真実  
です。  
DBは会社にとっての真実（Single Source of Truth）を管理するシステムです。  

### 2. データと処理を分離する
初心者は **Map<String, String> **  で持ちたくなります。  
しかしサーバ再起動で消えます。  
```text
つまり
プログラム
↓
処理担当
DB
↓
記録担当
```
と責務を分離します。

これはSpringの
- Controller
- Service
- Repository  
の考え方にも繋がります。

### 3. 一貫性(Consistency)
```text
DB最大のテーマ。
例えば銀行振込。
A口座 -10000円
エラー発生
B口座 +0円
```
だとおかしい。
あるべき姿は、** 全部成功 または 全部失敗 ** です。  
これがトランザクションの根本理由。  

### 4. 同時実行問題
DBが難しくなる理由は例えば、  
現在 在庫1個
Aさん 買う
Bさん 買う
同時。
結果:在庫マイナス1  になるかもしれない。

#### DBの設計
DBは**複数人が同時に触ること**を前提に設計されています。

### 5. 排他制御
同時実行問題への対策。
考え方は、今触ってるから**待って** です。

例えば
SELECT ...、FOR UPDATE　など。
つまり排他制御とは **整合性を守る仕組み** です。

### 6. 正規化
実は目的は **容量削減** ではありません。
本当は ** 矛盾防止** です。

悪い例
受注テーブル
山田
岡山市

山田
倉敷市
どっちが正しい？
分からない。
だから

顧客
注文
に分ける。

正規化の目的は、**データの真実を1箇所にする** です。

### 7. インデックス
時間と容量の交換
です。
索引を持つことで
ディスク消費↑
検索速度↑
になります。
コンピュータサイエンスで頻出のトレードオフです。

### 8. DBはメモリではなくディスクが相手
Javaだけやっていると
```text
メモリ
↓
ナノ秒
```
の感覚になります。

DBは
```text
ディスクアクセス
↓
ミリ秒
```
です。
100万倍くらい遅い世界です。
だから
**SELECT * ** や **N+1問題** が問題になります。

### 9. ACID
DBを理解するなら必須。
- Atomicity
- 原子性
- 全部成功
- 全部失敗
- Consistency
- 一貫性
- 矛盾しない
- Isolation
- 独立性
- トランザクション同士が干渉しない
- Durability
- 永続性
- COMMIT後は消えない  
DB製品はほぼこれを守るために存在しています。

### 10. DB設計で最も大事な考え方
SQLではなく、**何がエンティティか** です。　　
例えばECサイト。  
```text
初心者
商品名
顧客名
注文番号
```
全部1テーブルにしたくなる。

しかし設計者は
- 顧客(Customer)
- 商品(Product)
- 注文(Order)
- 注文明細(OrderDetail)  
という現実世界の概念を抽出します。
これがER設計。
実は SQL作成 より **現実世界をどうモデル化するか**の方が遥かに重要です。
